## 技術事實與評測口徑

- **推論與資料流。** 正式網站使用 Gemini。原型 Ollama/Qwen3.5 4B 經私人 Gateway、VPS loopback 與 SSH 反向通道。Home server 先建立連線；Express 驗證身分後才執行唯讀工具。單一生成、兩個等待槽，Agent 至多 5 次工具、1 次模型、38 秒總期限。模型不持有 MongoDB 憑證，也不接受從瀏覽器直接呼叫。
- **檢索與取證。** JWT 使用者限定在本人資料，包括本人的私人日記。MongoDB 計算精確統計。資料不足、無符合結果與錯誤分開回傳。引用需經授權、版本及原文範圍驗證；通過引用驗證不表示任意推論成立。
- **選型。** [原始評測還原與 SHA-256](agent-quality-phase45.md) 記錄固定題目、評分規則與原始紀錄位置。90.2/100 為三模型比較加權分；75.9 token/s 為暖機 4K 推論測試。約 3.13 GiB 為 [Phase 4 8K smoke](memory-agent.md) 結束時 Gateway 回報的模型 VRAM（3,364,911,840 bytes），不是整機或峰值量測。
- **驗證。** Phase 4.5 歷史結果為後端 224/224、Web 19/19，含單元、Mock、隔離 MongoDB；GPU 與私人通道另外驗證。原始模型 v1 嚴格 3/12 與 Agent v2.1 功能 5/12 的規則不同，不能換算成進步幅度。多輪 8/9 逐輪、1/2 完整；原始語意 5/20；獨立小集 7/8 只代表規則通過。早期兩組 100/100 是狹窄的統計與摘錄回歸檢查。參見 [Phase 4.5 報告](agent-quality-phase45.md)。

## 技術問答

| 問題 | 建議回答 |
| --- | --- |
| 為什麼用 Ollama？ | 可以在既有 Ubuntu 主機上管理模型與推論容量，並驗證私人通道，不依賴瀏覽器直接連模型。 |
| 為什麼選 Qwen3.5 4B？ | 在固定的 Adrift 三模型評測中兼顧工具參數與速度；4B 量化版本適合現有 8GB GPU。分數不是任意問題的回答準確率。 |
| 與 Gemini 差在哪？ | Gemini 是正式服務；Ollama 是本地可控的推論驗證，新增了維護硬體、連線與容量的責任，沒有自動回退到雲端。 |
| Agent 和一般 Chatbot 有什麼不同？ | 這裡的 Agent 有受控工具、可查的執行事件與引用驗證，不是只把對話交給模型生成。也不是無限制自治。 |
| 如何防止編造日記？ | 只有本次取回並驗證的 ID、版本和原文可被引用；統計由後端算。語意推論仍可能出錯，證據不足應保守表達。 |
| 如何保護私人日記？ | 本人的 AI 檢索以 JWT 身分鎖定所有權。公開與好友可見是一般瀏覽規則，不會讓 Agent 讀取別人的私人日記。正式 Gemini 處理必要的授權內容，本地版尚未替代。 |
| 長期間怎麼查？ | 先依臺北日期轉成 UTC 範圍，再分頁及取樣，只把相關證據放進 context。完整長篇與跨日事件歸併仍待改善。 |
| 8GB 夠嗎？ | 已驗證單一 Qwen3.5 4B 在 4K／8K 的受限任務；8K 小批觀測不是滿載測試，不保證更長 context、同時多模型或長輸出。 |
| 家中伺服器斷線怎麼辦？ | 通道可重連，Gateway 有有界等待、逾時與取消；錯誤隔離在 AI，正式站仍由既有 Gemini 路徑服務。 |
| 為什麼需要 AI？ | 地圖與統計能找出「在哪裡、記了幾次」。AI 的目的則是把提問連回有根據的生活片段，讓使用者自己重新理解；不代替原始資料或情緒判斷。 |

## 畫面、檔案與重現

- `PresentationPage.jsx`、`presentationSlides.js`、`presentation.css`：使用 Git 版原有的背景、字體、章節導覽、動畫、卡片、分工列及架構圖；只補內容、新版面所需的樣式與 PDF 輸出。共用 `styles.css` 未修改。
- `apps/web/public/presentation/`：Chrome 擷取的實際元件。Mapbox 底圖在本機載入；日記、帳號、角色、通知與統計均為合成資料。Chat 回覆為 fixture，非模型推論；Feed 的 [森林](https://images.unsplash.com/photo-1441974231531-c6227db76b6e) 與 [咖啡](https://images.unsplash.com/photo-1509042239860-f550ce710b93) 圖片是示意照，不是所述地點。未使用正式使用者資料。
- `apps/web/tests/presentation-capture.mjs`：以本機 API fixtures 重擷取畫面。需要 Chrome、Playwright 與可渲染 Mapbox 的本機設定。
- `apps/web/tests/motion-browser.mjs`：逐頁擷取、尺寸和控制測試；`--pdf` 以 Chrome 重新產生 `apps/web/public/Adrift-presentation.pdf`。WebKit 驗證使用 `BROWSER=webkit`，不是原生 Safari。
- `apps/web/tests/device-support-browser.mjs`：更新投影片辨識 selector，桌面與行動裝置政策不變。

從專案根目錄執行 `npm run presentation:pdf`。匯出會自動啟動本機 Vite；若沒有 Chrome，可用 `npx playwright install chromium`。使用與網頁相同的 React 元件，等待字型及圖片載入，再以 16×9 吋、無邊界產生 `apps/web/public/Adrift-presentation.pdf`。瀏覽器建置會核對簡報來源、PNG 與 PDF 的雜湊；若不符，先重跑匯出。若調整了共用樣式且影響投影片，也應重跑匯出。 `/pd` 以每次進入頁面時產生的新下載 URL 避免沿用舊快取。

瀏覽器驗收使用 `node apps/web/tests/motion-browser.mjs`，可設 `PREVIEW_URL`、`BROWSER=webkit` 或 `PLAYWRIGHT_MODULE`。驗收圖不進 Git。
